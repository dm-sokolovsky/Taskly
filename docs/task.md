# Taskly: задание и критерии готовности

## Назначение

Тестовое задание для вакансии начинающего разработчика сайтов и веб-приложений с AI-инструментами. Результат должен показать работающее приложение и осмысленную постановку задач AI, проверку и улучшение сгенерированного кода.

## Условия

- Создать простой веб-сайт «Список задач».
- Реализовать добавление, отметку выполнения и удаление задач.
- Сохранять задачи после обновления страницы.
- Дизайн свободный; интерфейс должен выглядеть аккуратно и работать корректно.

## Границы и решения

- Используем существующий React + TypeScript + Vite проект.
- Для небольшого списка достаточно локального состояния и `localStorage`.
- Backend, аккаунты, синхронизация между устройствами и дополнительные функции не входят в текущий объём.
- Сохранение относится к этому браузеру и origin сайта. Данные могут быть удалены пользователем или браузером; конфиденциальность хранения не гарантируется.
- Дополнительное требование Дмитрия: отдельная проверка безопасности приложения, зависимостей и качества кода.
- Дизайн, язык интерфейса и конкретный хостинг пока не выбраны.

## Критерии приёмки

Ниже — запланированные проверки. Их наличие в документе не означает, что они выполнены.

| ID | Сценарий | Ожидаемый результат | Проверка |
| --- | --- | --- | --- |
| F1 | Добавить непустую задачу кнопкой и через Enter | Задача появляется один раз с введённым текстом | Браузер |
| F2 | Добавить пустой текст или только пробелы | Пустая задача не создаётся | Браузер |
| F3 | Отметить задачу выполненной и вернуть в активные | Меняется только выбранная задача; состояние различимо визуально и доступно вспомогательным технологиям | Браузер, проверка разметки |
| F4 | Удалить одну из нескольких задач, затем последнюю | Удаляется выбранная задача; пустой список отображается корректно | Браузер |
| F5 | Поочерёдно добавить, завершить и удалить задачи, после каждого действия обновить страницу | Состав, текст и статус задач сохраняются, удалённые задачи не возвращаются | Браузер |
| U1 | Использовать интерфейс только клавиатурой | Все действия доступны, фокус видим, элементы имеют понятные названия | Браузер |
| U2 | Открыть на ширине 375 px и 1280 px, добавить длинный текст без пробелов | Нет горизонтального переполнения, текст читаем, кнопки доступны | Браузер |
| S1 | Добавить текст `<img src=x onerror=alert(1)>`, обновить страницу | Текст отображается буквально; код не исполняется ни до, ни после сохранения | Браузер, ревью |
| S2 | Подставить в хранилище некорректный JSON или данные неподходящей структуры | Приложение не падает, остаётся возможность работать со списком | Браузер, ревью границы чтения данных |
| S3 | Заблокировать запись в хранилище | Интерфейс не падает и не обещает успешное сохранение при его недоступности | Браузер или тест с подменой Storage |
| Q1 | Выполнить `npm run build` и `npm run lint` | Обе команды завершаются успешно | Команды из корня проекта |
| Q2 | Проверить обновления состояния и идентификаторы | Нет мутаций состояния, нестабильных ключей и записи в хранилище во время рендера | Ревью diff |
| Q3 | Проверить список из 100 задач | Ввод, переключение и удаление не вызывают заметных задержек; при задержках — профилирование | Браузер; записать окружение и наблюдения |
| S4 | Проверить зависимости и публикуемые файлы, включая историю Git | Нет секретов; существенные результаты аудита разобраны, ограничения описаны | `npm audit`, ревью файлов и истории без вывода секретов |

## Рабочий процесс

1. Зафиксировать задание и критерии → сверить с условиями работодателя.
2. Выбрать простой интерфейс и реализовать обязательные функции → проверить F1–F5.
3. Провести отдельное ревью кода и безопасности → разобрать Q2 и S1–S4, исправить подтверждённые проблемы.
4. Проверить окончательный код → выполнить весь применимый набор сценариев и записать фактические результаты.
5. Подготовить сдачу → актуальный README, GitHub, описание AI-инструментов и при публикации ссылка на сайт.

Проверки безопасности учитываем при реализации; отдельное ревью проверяет итог. Оптимизации добавляем по обнаруженной потребности. Новые зависимости должны решать конкретную задачу.

## Условия сдачи

- Все обязательные функции реализованы и проверены.
- README содержит актуальные команды запуска, возможности, AI-инструменты, фактические проверки и существенные ограничения.
- В журнале различаются результаты агента и самостоятельная проверка Дмитрия.
- Незавершённые проверки и нерешённые замечания явно обозначены; критичные проблемы исправлены до сдачи.
- Ссылка на GitHub доступна проверяющему; опубликованный сайт, если подготовлен, проверен по основным сценариям.
